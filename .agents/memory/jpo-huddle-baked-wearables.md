# Baked wearables (Phase 3)

- Most wearables are BAKED into the player texture per frame instead of overlay sprites. Anchors (`public/assets/layers/anchors.json`, from `tools/wearable-anchors.cjs`) give per-frame head-top/head-center/feet from the split layers; the client keeps each item's approved standing-pose offset (def dy/side ÷3 = texels) and shifts by the anchor delta of the target frame — including seated sheets.
- NOT baked: wings (live flap tween + behind-body ordering) and scifihelmet (non-integer 4.4 scale). They stay overlays via `_makeCosmetic`, which is also the automatic fallback whenever bake assets aren't ready.
- Raincoat is a LAYER REPLACEMENT: sheets generated by `tools/cosmetic-layer-gen.cjs` from each character's shirt∪pants silhouette (shirt alone is a sliver on some chars — reads as a belt, not a coat). Include dark outline pixels via region fill + luminance tinting or the coat looks patchy; leave the bottom 3px per column for boots; hair drapes over.
- Tex keys append `_W<sorted ids>`; sit tex/anim keys derive from the run key so pose logic needs no changes. Worn state lives on `entry.wear`/`entry.appear` for remotes; any equip change must rebuild the texture (local `_applyLocalOutfit`, remote `_updatePlayerCosmetics` → `_applyRemoteOutfit`).
- **Readiness race rule:** anchors.json + coat sheets load async; sprites built earlier baked nothing and got overlays. Every settle path must call `_rewearAll()` (re-dress local + all remotes) — a stationary/seated remote never gets a later outfit event to fix itself. Same class of bug as the layer-image legacy-texture race.
- Wide art (headphones 18px) is clip-rected per frame so it can't bleed into neighbor frames; left rows are drawn mirrored from the right-facing art frame.
- Known accepted growth: texture cache is unbounded per palette+wear combo (matches pre-existing palette cache design; small player counts).
- Browser tests live in /tmp/jpotest (`baked_wear_test.cjs`): seed approved row FIRST, register, equip via SQL UPDATE of equipped_* columns, reload. Set localStorage `jpo_tutorial_seen=1` via evaluateOnNewDocument or the first-login tour covers screenshots. ## Feet-gear dy gotcha (Aug 18 2026)
- Baked wearable Y = texel 16 + dy/3 (anchor delta cancels on run frames where a.fy==ref.fy), so a def dy tuned "by eye" can strand feet gear at the shins where it blends into the outfit and looks missing. Feet rows are 28-31 → rainboots need dy 42, not 25.
- Verify placement numerically: dump the baked sheet via in-page _buildPlayerTex + canvas toDataURL, then grep the boot palette rows with magick txt:.
- `_wearAnchors`/DIR_START are closure-scoped, NOT on window — a harness reading window._wearAnchors always sees undefined; judge bake readiness by the rendered pixels instead.
- Umbrella reads as HELD by extending the art itself (22px tall: canopy + shaft + J-hook to the hand rows ~19-20, dy -15). Front/back shafts must slant sideways to the hand — a straight center shaft draws through the face.
- Clothing = LAYER sheets, not stickers (Aug 2026): shirts/pants/footwear items should paint the sprite's own pixels (tools/cosmetic-layer-gen.cjs pattern; boots via tools/boot-layer-gen.cjs paint each column's bottom-3 rows). Overlays are only for items that genuinely sit ON the character (hats, held). Slots: top/bottom/neckwear/held/feet + legacy hat + wings.
- Fitting-room QA: tools/wearable-fitcheck.cjs dumps a 4-direction contact sheet per item — run it for every new/changed wearable before presenting.
- Hooded coat lesson (Vince-approved look): a hood must be its OWN drawn geometry — ellipse from the head bbox, crown peak, drape to the shoulder line, neck taper below cheek level. Recoloring hair pixels (or building the dome from hair columns) reads as "yellow hair" and was rejected twice. Layers can't erase base pixels, so the hood must be a superset of every hair pixel. Bump the ?v= cache param on /assets/layers URLs whenever sheets regenerate.

## Cape readability
Capes need a broad, shoulder-to-ankle drape with visible flared sides while leaving front-facing torso, arms, and face readable. Do not shrink them to thin shoulder strips to avoid covering the avatar.

**Why:** The initial Halloween cape was rejected as a front panel; the tiny silhouette-masked revision was also rejected. The user explicitly wanted it longer and wider, recognizable as a cape.

The user explicitly loved the full rounded pumpkin replacement and broad, long cape. Preserve that design when fixing pose bugs; do not shrink or redesign it again.

**How to apply:** Allow pose-tracked overlays to extend beyond native body-frame bounds instead of clipping broad garments. Inspect tightly cropped native standing/seated renders in every direction, including combinations with owned seasonal layers. Full-head replacements must cover original hair/head, not merely stamp a face on top.

Seated-sheet direction names describe chair mappings, not reliable anatomical facings. Inspect native frames (including their second halves) before choosing cape orientation.

**Why:** Treating the down-seat sheet as a front-facing body produced a cape apron over a profile pose. When placing cape below body, keep head replacement above the body—not just above the cape.

## Full-head animation coherence
Derive a rigid head replacement from one approved pose per direction, then translate with the native crown motion; don't reshape its ellipse from changing shirt/hair bounds.

**Why:** Frame-dependent bounds distorted pumpkin geometry, while packet-driven overlay updates lagged remote body animations. Both read as the pumpkin lifting away during walking.

**How to apply:** Synchronize pose overlays after native animation advances, not just on movement packets. Verify the whole gait cycle, including opposite-phase final frames and remote animation without incoming packets.
