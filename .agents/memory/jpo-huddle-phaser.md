# Sprite sheet layout — all 4 characters

All characters use a 384×224 (24 cols × 7 rows = 168 frames, 16×32 per frame) sheet:
- adam → Adam_16x16.png (original full LPC sheet)
- alex → Alex_16x16.png (synthesized from Alex_run_16x16.png)
- amelia → Amelia_16x16.png (synthesized from Amelia_run_16x16.png)
- bob → Bob_16x16.png (synthesized from Bob_run_16x16.png)

Alex/Amelia/Bob full sheets were generated by Python (PIL) from their single-row run sheets:
- Row 0 (frames 0-23): original 24 run frames
- Row 2 (frames 48-55): frames 0-7 flipped vertically (walk_up)
- Row 3 (frames 72-79): frames 0-7 flipped horizontally (walk_left)
- Row 4 (frames 96-103): frames 0-7 as-is (walk_right)

# Animation key format and frame spec

Phaser texture key = character name (`adam`, `alex`, `amelia`, `bob`).
Animation keys: `${char}_idle`, `${char}_walk_down`, `${char}_walk_up`, `${char}_walk_left`, `${char}_walk_right`.

All 4 characters use identical frame ranges:
- idle: 0–3, walk_down: 0–7, walk_up: 48–55, walk_left: 72–79, walk_right: 96–103

Adam-specific extras: `sit_adam` (adam_sit, frames 0–5), `phone_adam` (adam_phone, frames 0–8).

**Why:** Uniform frame layout eliminates per-character branching and simplifies server↔client anim state mapping.

# Directional movement — no flipX

Characters have proper left/right walk animations; `setFlipX` is NOT used anywhere.
- left → `${char}_walk_left`, right → `${char}_walk_right`
- up → `${char}_walk_up`, down → `${char}_walk_down`
- stopped → `${char}_idle`

Animation state in `playerMove` emit: `idle`, `sit`, `walk_down`, `walk_up`, `walk_left`, `walk_right`.

# Character assignment

- Randomly assigned on page load: `CHARACTERS[Math.floor(Math.random()*CHARACTERS.length)]`
- Server confirms character in `approved` event; `_playerChar` updated then.
- No palette-swap system; characters display native sprite colors.

# Registration flow

- No character builder. Name + email → "Request Access →" → pending → admin approves → office.
- `reg-submit-btn` triggers `tryRegister()` directly (Enter key on any field also works).

# Phaser arcade body sizing

- At `setScale(3)`, body dimensions are multiplied by 3 for collision.
- Keep body ≤ 36×36 source to fit through 1-tile (48px) doorways. Use `body.setSize(12,12)`.

# TilemapLayer render ordering — CRITICAL

- `setDepth()` unreliable relative to Physics sprites in Phaser 3.80.1.
- Use insertion order only: Floor → Wall → Furniture → other-player sprites → local player.

# Office.tmj map

- Some rooms are sealed (Wall layer encloses them with no gap). Must be fixed in Tiled.
- Spawn point: tile (22, 17) = world (1080, 840).
- World size: 2400×1728 (50×36 tiles × 48px).
