# Adam player spritesheet
- `public/assets/Adam_16x16.png` is **16×32 per frame**, NOT 16×16 (the filename misleads — the character spans two tiles tall). Each 32px frame holds one full character; frames are cleanly aligned, no misalignment.
- **So a "cut character" is NOT a spritesheet/frameHeight problem** — look at TilemapLayer insertion order (see below).

# Run sheets are 4-directional (24 frames) — NOT side-only (supersedes old flipX approach)
- Every `*_run_16x16.png` (Adam, Alex, Amelia, Bob) is 384×32 = **24 frames = 4 directions × 6**: RIGHT 0–5, UP (back-of-head, no face) 6–11, LEFT 12–17, DOWN (front, full face) 18–23.
- **Why the old "side-profile only, flipX for left" belief was wrong:** confirmed by counting skin-colored pixels in the face band per frame — UP rows ≈0 face skin, DOWN rows have the most (centered), and the two side rows mirror each other. Dedicated LEFT and RIGHT rows both exist.
- **How to apply:** never flip a side frame for the opposite side and never flip to fake up/down — use the real rows. Keep `setFlipX(false)` everywhere; there is no `lastFlipX` anymore.
- **Front frame 18 is the "portrait":** character-builder preview + hair-style thumbnails must draw source x=288 (frame 18) so every character shows its face. Drawing frame 0 (side view) makes long-haired characters (Amelia) look faceless/"broken".

# Directional animation setup (current)
- Per texture key `k`, `_createDirAnims(k)` builds `idle_${k}` (single frame = DIR_START.down = 18) + `walk_${k}_${dir}` for right/up/left/down. Idempotent (guarded by anims.exists). Called for base `run_${char}` and per-player `pl_...` textures.
- update() picks facing from input (vertical sets dir, then horizontal overrides so diagonals show a side view), plays `walk_${texKey}_${dir}`; when not moving, `anims.stop()` + `setFrame(DIR_START[lastDir])` to hold last facing. Track `this.lastDir` (default 'down') and `this._moving`.
- **Network protocol carries `dir`, not flipX:** emit `{x,y,dir,anim}`. Validate incoming dir with `DIR_START[data.dir] !== undefined ? data.dir : 'down'` — note `DIR_START.right === 0`, so test `!== undefined`, never truthiness (a `data.dir || 'down'` fallback silently drops a valid 'right').
- Chat/owner-panel idle must preserve facing (`setFrame(DIR_START[lastDir])`, skip if sitting) and still emit a throttled idle/sit update, or remote clients keep seeing your last walk animation while you type.

# Sit is DIRECTIONAL (3 sheets) — right/up/down, left mirrors right
- Adam has THREE seated sheets, and their per-frame PITCH is NOT uniform: `Adam_sit_16x16.png`=RIGHT (384×32, **32px pitch**, 12f), `Adam_sit2_16x16.png` (384×32, **32px pitch**, 12f — mapped to the 'up' slot but **NOT a back view**: skin-pixel counting shows ~41 face px like the RIGHT sheet vs ~3 for a genuine run-sheet UP frame; it's a face-visible profile pose), `Adam_sit3_16x16.png`=DOWN/face (192×32, **16px pitch = 12f**, poses packed edge-to-edge — do NOT read this as 6f/32px). All anims use frames 0–5. There is NO left sheet — LEFT reuses the RIGHT sheet with `setFlipX(true)` (every one of sit's 12 frames faces right; the back half is not a left variant). `SIT_SHEETS={right,up,down}` + `SIT_DIR={right:right,left:right,up:up,down:down}`. **A true seated back-of-head look is only achievable via the 'standup' pose** (standing UP run frame + chair-tile occluder) — see jpo-huddle-sit-facing.md.
- Per-player build loops SIT_SHEETS → palette-swapped textures `pl_sit_${dir}_...` + anims `sit_${key}_${dir}` (keyed off the run texKey, like walk). Base `sit_adam_${dir}` anims exist but are dead code — render always uses the per-player keys.
- **Sit facing lives at THREE render sites and all must agree:** local `update()`, remote `playerMoved`, remote `_addOtherPlayer`. Each must pick `sit_${texKey}_${SIT_DIR[dir]||'down'}` and `setFlipX(dir==='left')` when that anim exists; else fallback `setFlipX(false)` + standing frame `DIR_START[dir]`. Miss the dir/flip at ANY one site and that class of sitter (self OR remote) always faces right — the original bug was a single `sit_${texKey}` anim plus an unconditional `setFlipX(false)`. Green manager desks face 'left', so they are the mirrored case to test.
- **"Faces the wrong way (e.g. right) until you sit AGAIN" = a STALE `currentAnim.key` guard, NOT facing data and NOT a walk→sit transition.** The seat render guard was `if (currentAnim?.key !== sitAnim) play(sitAnim)`. But `anims.stop()` does NOT null `currentAnim`, and stand-up does `player.setTexture(playerTexKey)` which ALSO leaves the old sit `currentAnim` intact. So on a re-sit WITHOUT walking in between (walking would set `currentAnim` to a walk key and mask it), `currentAnim.key` still equals `sitAnim` while the anim is STOPPED and the sprite is frozen on the standing run-sheet frame (facing whatever you last walked). The key-only guard concluded "already seated" and skipped `play()`. Confirmed by logs: failing sit had `cur=sit_..._down` but `tex=pl_adam`(run) `frame=18`; working sits had `tex=pl_sit_down frame=0`. **Fix (all THREE render sites): also re-play when not actively playing** — `if (currentAnim?.key !== sitAnim || !anims.isPlaying) play(sitAnim)`. `play()` (Phaser 3.80, default ignoreIfPlaying=false) restarts + sets the first frame's texture/frame synchronously, so no explicit `stop()`/`setTexture(f0)` is needed; and because sit anims are `repeat:-1`, `isPlaying` stays true once started, so `!isPlaying` fires exactly once per re-entry (no per-tick re-play/flicker). The earlier "walk→sit transition" theory (prescribing `stop()` + forced `setTexture(f0)` inside the key-only guard) was WRONG and DID NOT fix it — do not reintroduce it. `_addOtherPlayer` uses a freshly-created sprite (no stale anim), so a plain `play(sk)` is correct there. General lesson: **any "already playing this anim" guard keyed on `currentAnim.key` alone is unsafe — check `isPlaying` too, because `stop()`/`setTexture()` leave a stale key.** Don't confuse this with the always-faces-right symptom (a facing-data/flip bug) or a stale cached build (see conference-chairs note).

# Seated-sheet frame pitch is PER-SHEET (32px for sit/sit2, 16px for sit3) — wrong pitch = sway OR a twin
- Pitch is NOT uniform across the three sit sheets and the "16x16" filename lies about all of them. **sit (RIGHT) and sit2 (UP) are 32px per pose** (figure centred with padding in a 32px cell; 384px = 12f). **sit3 (DOWN) is 16px per pose** (poses packed edge-to-edge, no padding; 192px = 12f).
- **Two DIFFERENT symptoms from the wrong pitch — don't conflate them:** (a) slicing a genuinely-32px sheet (sit/sit2) at 16px halves each pose and the loop alternates the halves → on-screen left-right SWAY; (b) slicing the genuinely-16px sheet (sit3) at 32px MERGES two adjacent poses into one frame → renders **TWO identical characters one tile apart (48px at scale 3) under one name tag** — the long-standing "duplicate on sit / same dude goes right and left" report, which is NOT a networking/remote-player dupe.
- **Fix:** slice EACH sheet at its own pitch. Preload: `adam_sit`/`adam_sit2` at `frameWidth:32`, `adam_sit3` at `frameWidth:16`. In `_buildPlayerTex` the palette-swapped `addSpriteSheet(sitKey,…)` must mirror this: `frameWidth: dir==='down' ? 16 : 32`. Keep anims at frames 0–5. `_applySwaps` runs on raw pixels with its own `frameW=16` BEFORE slicing, so slice width never affects palette swaps or remote avatars.
- **Key lesson — animation-frame issues are invisible to transform probes:** `player.x/y` never move, only the rendered frame pixels change, so position/physics jitter checks read exactly 0 and miss BOTH the sway and the twin. Diagnose by rendering the source sheet enlarged and counting poses/pitch (or diffing screenshots across anim frames), never the sprite transform.

# player.texture.key drifts during sit animation
- Palette-swapped animations (e.g. `sit_pl_adam_h1_sk0_sh2_p3`) reference frames from a *different* texture than the run sheet. Phaser switches `sprite.texture` when playing them.
- **Never use `player.texture.key` to derive walk/idle/sit animation keys** — it returns the sit texture key after the sit anim plays, and `walk_<sit_tex>` / `idle_<sit_tex>` do not exist → `anims.exists()` guard silently blocks `play()` → character freezes on sit frame.
- **Fix:** store `this.playerTexKey = texKey` in `_onApproved`. Use `this.playerTexKey` everywhere in `update()`. On E stand-up, call `player.setTexture(this.playerTexKey)` immediately before the next `update()` tick.

# playerMoved animation keys must use texKey not character name
- Other players' sprites use palette-swapped textures (e.g. `pl_adam_h1_sk0_sh2_p3`). Building animation keys from `entry.character` (`walk_adam`) references frames from the base `run_adam` texture — Phaser switches the sprite's texture on every frame → visible color flash.
- **Fix:** store `entry.texKey` in `otherPlayers[]` and use it when building animation keys in the `playerMoved` handler.

# Idle trigger — key-state NOT velocity
- Use `!left && !right && !up && !down`, NOT `velocity.x === 0 && velocity.y === 0`.
- Velocity check fires during wall collisions even while keys are held → rapid idle↔walk flicker.

# Phaser arcade body sizing gotcha
- Arcade `body.setSize` dimensions ARE multiplied by the sprite's scale for world collision.
- **Why:** at `setScale(3)`, a `16×32` body becomes 48×96 = two 48px tiles tall. A 2-tile-tall body silently cannot fit through 1-tile horizontal doorways.
- **How to apply:** keep body ≤ 36×36 source (< 1 tile = 48 world px). **Feet-center it** with `setSize(12,10).setOffset(2,20)` — the default (offset-less) auto-center lands the body on the character's TORSO (the tile row ABOVE the feet), which silently blocks aisles one row below furniture (this was the "can't walk past furniture" bug). With the feet body, the tile the player OCCUPIES is `floor((player.y + 27)/48)` at scale 3 (27 = world-px from sprite origin/center down to body-center); derive interaction/tile lookups from that, not `player.y`.

# TilemapLayer render ordering — CRITICAL
- **`TilemapLayer.setDepth()` does NOT work reliably relative to Phaser Physics sprites in Phaser 3.80.1 WebGL renderer.**
- **Fix: use insertion order only, and it MUST mirror the Tiled layer stack (bottom→top: Floor, Furniture, Wall).** Create objects in this sequence:
  1. Floor layer
  2. Furniture layer
  3. Wall layer ← holds the upper/back parts of desks & chairs, so it MUST render ON TOP of Furniture
  4. **Other-player sprites** ← runtime-added, always end up on top
  5. **Local player sprite** ← last = always on top of everything
- **Wall must be created AFTER Furniture.** The earlier bug created Furniture last, which made office chairs float ON TOP of the desks/computers they should tuck under. In Tiled the chair backs live on the Wall layer and desks/monitors on Furniture; wherever they share a cell the Wall tile must win. The game's `createLayer` order has to match the `.tmj` bottom→top order or the running game disagrees with what the user sees in Tiled.
- Player/other-player sprites carry no `setDepth` (default 0) and are created AFTER all tile layers, so insertion order keeps them above every layer including Wall — Wall-on-top does NOT occlude the player (earlier attempts that put the player before furniture made it ghosted/invisible behind desks; keep it last).
- Remove all `setDepth` calls from TilemapLayers. Never rely on depth to lift a sprite above a tile layer.

# Tuck-seated-body-under-desk = per-seat OVERLAY sprites (NOT layer depth)
- The seated player (depth 0, created last) renders ON TOP of the desk/monitor tiles, so a sitter looked like they sat ON the desk. `TilemapLayer.setDepth` is unreliable here and reordering layers/player is forbidden (above), so the fix is: **on sit, DUPLICATE the occluding desk tiles as high-depth (`setDepth(900)`) `this.add.image` overlays; destroy them on stand.** Sprite-vs-sprite depth IS reliable, so 900 > player's 0 makes the body tuck under.
- Tilesets are ALSO loaded as 16×16 spritesheets (`roombuilder_ss`/`interiors_ss`/`ext_ss`) purely for these overlays. **Overlay frame index = `gid - firstgid`** — exact ONLY because all three tilesets have `margin:0, spacing:0` (verified) so Phaser's spritesheet slicing matches Tiled's tileset slicing. `_gidToSheet(gid)` thresholds: `>=1816` ext, `>=392` interiors, else roombuilder. Draw at world `(c*48, r*48)`, `setOrigin(0,0).setScale(3)`.
- **Which tiles to overlay is seat-type-specific:** workstation chair (GID **606 only**) → Wall tiles at the chair cell (monitor 453) + the facing-dir cell (desk-front 469). Manager desk (`DESK_FAMILIES`) → Furniture tiles at/BELOW the chair row, EXCLUDING the chair cell, and NEVER rows above (the 2-tall sprite's head lives one tile up). **Gate the Wall branch strictly to 606** — sofas/benches legitimately share a cell with structural wall GID 64, so a generic "overlay the Wall tile at the seat" would draw a wall over the sitter.
- Lifecycle at ALL sit render sites: local `update()` (store in `this._seatOccluders`), remote `playerMoved` + `_addOtherPlayer` (store on `entry.occluders`, guard create with `!entry.occluders`, clear when `anim!=='sit'` and in `_removeOtherPlayer`). Remote seat cell is the inverse of the sit snap: `col=round((x-24)/48), row=round((y-24+BODY_DY)/48)`.
- **Overlays ignore tile FLIP flags** (`add.image` can't reproduce `tile.flipX/flipY`). All currently-overlaid GIDs (453/469, 959–996) are unflipped in Office.tmj so it's fine today — but a future map that flips a desk/monitor tile would render the overlay unflipped (mismatched). Re-check on map swaps.
- Accepted minor tradeoffs (not bugs): a different player walking onto a desk-front/monitor cell while someone sits is briefly clipped by that sitter's depth-900 overlay (nameTags at 1001 stay visible); overlays only exist while seated so walking sitters are never affected.

# Custom (non-tilemap) furniture sprites — split-crop pattern
- A visible object that is NOT in Office.tmj (e.g. the Pantry water cooler) is best drawn as TWO `add.image`s of ONE tall texture at the SAME position/origin, using `setCrop` texture-space rects: bottom half at default depth 0 created in `create()` (players, created later, draw in front), top half at depth 900 (the seat-occluder convention) so players on the row BEHIND are occluded. `setCrop` never moves display bounds, so no offset math — the halves tile seamlessly.
- Block its footprint with a static physics `zone` + collider on the player (client-side only; the server's movement validation has no tile collision, and that's fine for cosmetic furniture). Keep the tile behind (where the top half draws) walkable so the occlusion actually shows.
- **Why:** TilemapLayer depth is unreliable (see above) and editing Office.tmj is off-limits between user re-imports; sprite-vs-sprite depth + insertion order is the only dependable layering.

# Office.tmj map (user-authored in Tiled, swapped in periodically)
- **The served `Office.tmj` MUST carry EMBEDDED tileset defs** (each with `name` + `image` + `firstgid` + dims), because the Phaser loader resolves tilesets by NAME via `map.addTilesetImage('<Name>','<imgKey>')`. A raw Tiled export (`.tmx` CSV or direct `.tmj`) often references tilesets as external `{firstgid, source:"X.tsx"}` with **no name/image** — those silently fail to render. Convert by taking the export's layer `data` (matched by layer NAME: Floor/Wall/Furniture) and pairing it with embedded tileset defs copied from the previous working `Office.tmj`. **Preserve flip-flag GID ints verbatim** (e.g. 1610612800, 3221225536 = base GID + Tiled flip bits, mask with 0x1FFFFFFF to read the real GID); Phaser strips them at render.
- **A new tileset in the export needs three wired-up steps or its tiles render blank/green:** (1) stage its image PNG under `public/assets/`, (2) `this.load.image('<key>', ...)` in preload, (3) `addTilesetImage('<Name>','<key>')` in create AND add it to the `tilesets` array passed to EVERY `createLayer`. Verify the PNG dims equal `columns*16 × ceil(tilecount/columns)*16` and firstgid doesn't overlap other tilesets. (The current map added an `Ext` exterior tileset, firstgid 1816, `tilemap_packed.png` 192×176/132 tiles, on top of Room_Builder firstgid=1 + Interiors_free_16x16 firstgid=392.)
- **Map dimensions can change between swaps** — never hardcode them. World size = `width*48 × height*48` (tile = 16px × scale 3); update `WORLD_W`/`WORLD_H` to match. **Re-validate spawn every swap:** the old spawn tile can become wall/furniture-blocked. Pick a spawn inside the LARGEST connected walkable component (flood-fill, walkable = floor!=0 AND wall==0 AND furniture==0 after masking flip bits). Current map is 63×36, world 3024×1728, spawn tile (28,17).
- **Faithful conversion reproduces the source's design quirks — do NOT "fix" them in code.** User layouts routinely include sealed cubicle interiors (Wall layer fully encloses cells, no doorway) and decorative board-art tiles (BOARD_GIDS) embedded in exterior/double walls with no walkable neighbor, plus the odd chair boxed in by its own cluster. These aren't conversion bugs — opening/relocating them means editing the Tiled source (redesign), out of scope for a straight swap. Validate with flood-fill + chair/board adjacency, then REPORT gaps for user signoff rather than fabricating doorways.
- **Screen-glow ambiance must be anchored to explicitly identified monitor tiles in the CURRENT source, never hardcoded tile coords** — hardcoded coords silently point at the wrong furniture (or empty floor) after any map swap.

# Furniture collision + sit model + announcement boards
- **COLLISION IS FURNITURE-SOLID-EXCEPT-SEATS (superseded the earlier walls-only model — walking straight through fridges/plants looked silly and the user reported it).** BOTH layers start solid: `wallLayer.setCollisionByExclusion([-1])` AND `furnitureLayer.setCollisionByExclusion([-1])`. Then ONE loop over every cell (a) opens the Furniture-layer SEAT tiles (`FURN_SEATS`) so chairs are walkable/steppable, and (b) opens Wall-layer desk pieces (monitors 453/523 + desk-fronts 469/539) on any wall tile that has a seat on it OR directly above OR below it. Derived from the loaded map, NOT a hardcoded GID list, so it survives Tiled re-imports. **Why:** packed seat banks put a wall-layer desk piece on every tile touching a chair, so middle chairs had zero adjacent floor and were unreachable — opening the seats + their desk pieces makes all 174 seats reachable while everything else (fridges/cabinets/plants/manager-desks) stays SOLID. **How to apply:** verify with the offline flood-fill on Office.tmj under this exact model (furniture solid except FURN_SEATS; wall solid except seat-adjacent desk pieces) — last check: 174/174 seats reachable, 9/9 manager desks have a reachable neighbour.
- **The brown "classroom"/workstation chair is a SINGLE Furniture-layer tile: GID 606 (103 of them).** It shares its cell with a monitor (Wall 453/523) and sits directly ABOVE a desk-front tile (Wall 469/539). **469/539 are the DESK, NOT the seat** — an earlier model listed them as `WALL_SEATS` and the player sat on the desk edge, and front-row chairs whose desk had a wall below became unreachable (this was the "can't sit in the brown chairs" bug). Verify tile identity by rendering: `magick Interiors_free_16x16.png -crop 16x16+X+Y` where X=(gid-392)%16*16, Y=floor((gid-392)/16)*16 (Interiors firstgid=392, 16 cols) — 453 rendered as a monitor, 606 as a brown chair. Model now: seating is one Furniture-layer allowlist `FURN_SEATS` (606, wooden 750/751, conference 510/472/474, sofas/benches); the E-scan probes ONLY the furniture layer. No wall-layer seat probe exists anymore.
- **To make new furniture sittable, two conditions BOTH matter:** (1) add its GID to `FURN_SEATS`, and if the tile art has a fixed orientation give it a `SEAT_FACING` entry (else facing falls back to the approach direction), and (2) the seat must be reachable — either you can walk ONTO it (the E-scan now checks the tile you're STANDING ON, before the 4-neighbour scan) or a walkable neighbour is reachable from spawn. Adding a GID to FURN_SEATS ALSO opens the seat's OWN furniture tile (so you can step onto it) AND the wall-layer desk tiles on/above/below it (see the furniture-solid-except-seats collision bullet), so new packed banks become enterable automatically. Under this model all 174 seat tiles are reachable — the old "~20 boxed-in chairs are faithful, leave them" note is OBSOLETE. Multi-tile sofas/benches: a backrest tile reachable from the far side lets the player perch on the backrest — harmless cosmetic quirk; trim to seat-surface tiles if a playtest looks wrong.
- **Beware sofa-look-alikes:** shelf/counter tops (e.g. 1490/1491 vending units, top-wall counter tops 1538-1543/1570-1573) resemble sofa cushions in the tiny palette — confirm by rendering the region in context before adding, or players "sit" on shelves.
- **A FURN_SEATS GID can coincide with a structural Wall-layer tile — gate seats PER-TILE, not just per-GID.** The study-desk unit is Furniture 1005 (desk, left tile) + 1006 (chair, right tile, faces 'left' toward the desk). But the classroom's east column (c23) draws the 1006 chair UNDER structural wall GID 64. Putting 1006 in FURN_SEATS globally OPENED that wall (the seat-adjacent wall-opening rule) and let a player on the open pantry floor at (24,34) face in, get an "[E] Sit" prompt and sit INSIDE the wall. **Fix:** a scene helper `this.isFurnSeat(gid,c,r)` used at ALL four seat checks (the two collision openings + both E-scan branches, replacing raw `FURN_SEATS.has(...)`) returns false for a 1006 tile whose cell also has a Wall tile. c17/c20 chairs (open floor) stay sittable; c23 stays a solid wall. **Keep the exclusion GID-specific:** other seats (wooden settle 1679…, waiting benches 1210…, sofas) legitimately share cells with wall GID 64, so a blanket "never open wall GID<392" guard would break them. **How to apply:** whenever you add a new seat GID, first check it doesn't overlap a Wall tile anywhere in the map (a quick offline scan), and prefer the per-tile `isFurnSeat` gate over a raw `FURN_SEATS.has()`.
- **Sitting snaps the player ONTO the seat tile so the feet-body CENTER lands on the tile center:** `setPosition(col*48+24, row*48+24 - 27)` — the −27 lifts the sprite origin above body-center so the character rests IN the chair, not straddling it. Save `_preSitPos` (the walkable tile you came from) and `body.enable=false` while seated so the solid collider can't eject you; on stand use `player.body.reset(preSit.x,preSit.y)` THEN `body.enable=true` (reset re-syncs body + prev position even while disabled; plain setPosition can leave the body stale for a tick and strand the player). **Facing is per-GID via `SEAT_FACING` for seats whose desk is on a consistent side of the tile** (750/751 face right/left toward the shared desk). The 606 workstation chair is pinned to **'down'**: its desk + monitor are ALWAYS directly BELOW the chair (verified — every one of the 103 has a desk-front Wall tile 469/539, a few 459, in the cell below), so 'down' is universally correct. The earlier "omit 606 so it uses the approach direction" model was a BUG — walking in from the side (approach dir = left/right/up) seated the worker facing sideways instead of at their monitor (user report: "not looking down the way I sat him"). **Sofas & benches get a PER-PIECE SEAT_FACING** (user: seated players should "face the way the sofa faces," not the aisle they walked in from). In THIS map, none carry flip flags: purple 2-seat (1583/1584/1599/1600), gray sectional (1548-1597) and waiting benches (1210/1211/1226/1227) all have their backrest at the TOP -> 'down'; but the wooden settle (1679/1680/1695/1696/1711/1712) is a SIDE-VIEW piece with its tall back on the RIGHT -> 'left'. **Don't assume 'down' — derive each by rendering the tileset art AND an in-map composite crop** (crop from a full map render at 16px/tile; a low-res thumbnail made the settle look down-facing but at high res its back is clearly on the right). A future map that flips or re-places a sofa must be re-derived the same way. Only fall back to approach direction for seats with no consistent orientation.
- **Conference chairs need PER-TILE facing, not per-GID.** The three conference-chair GIDs (472/474/510) ring a shared table and the SAME GID (510) is reused on the top, left, right AND bottom edges, so no single `SEAT_FACING[gid]` can be correct. Instead `create()` builds `this.seatFacingAt` (`"c,r" -> dir`) by scanning each conference-chair tile's 4 orthogonal neighbours for a conference-table GID (`CONF_TABLE_GIDS` = 488-490/504-506/520-522) and facing that way. Sit resolution priority is `seatFacingAt[tile] || SEAT_FACING[gid] || approachDir`. The general rule the user chose is "always face the desk/monitor in front of the seat"; a seat whose furniture is on a consistent side uses per-GID, one whose same-GID art surrounds shared furniture uses per-tile. **Note:** the workstation-chair "facing right" bug report that kicked this off was a STALE CACHED BUILD (606 was already pinned 'down' at all render sites) — the build-stamp cache-buster on workflow restart clears it; don't chase a code fix for a facing report before confirming the client reloaded.
- **Boards are wall-mounted on multiple sides** (including the right wall), so board/sit interaction must scan all 4 neighbours, not just the tile below — a below-only check misses side-wall boards.
- **`BOARD_GIDS` lists every real announcement board the user wants readable** — cork bulletins (682-685/698-701/714-717), colorful notice/bulletin boards (1013/1014 top, 1029/1030 base — the 2-wide colorful grids; per explicit user request these ARE boards, NOT "just shelves"), green chalkboard on stand (1042/1043/1058/1059), and blackboard (1045/1046 top, 1061/1062 base).
