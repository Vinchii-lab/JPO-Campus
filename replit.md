# JPO Huddle

A top-down multiplayer virtual office (a Phaser 3 game) for the JustPressOne team: people walk around as pixel avatars, chat, earn coins, buy cosmetics, and read the announcement board. All game state is durable in Postgres.

## Run & Operate

- `pnpm --filter @workspace/jpo-huddle run dev` — run the JPO Huddle game server (`node server.js`)
- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/jpo-huddle run loadtest -- --n 100 --duration 60` — headless load test (see `loadtest/README.md`; last verdict: `loadtest/RESULTS.md` — PASS at 100 players)
- Required env: `DATABASE_URL`; `ADMIN_PASSWORD` (gates the in-game admin panel); `SESSION_SECRET` (signs auto-rejoin resume tokens; unset = auto-rejoin disabled)

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5 · DB: PostgreSQL + Drizzle ORM · Validation: Zod (`zod/v4`), `drizzle-zod` · API codegen: Orval

## Where things live

- `artifacts/jpo-huddle/server.js` — the whole game server: Express 5 static serving (cache-busting `BUILD_STAMP`), socket.io handlers, all DB access via a raw `pg` Pool. Plain ESM, `node server.js`, no build step.
- `artifacts/jpo-huddle/public/index.html` — the entire client (plain JS, Phaser 3 + socket.io from CDN, no bundler). Source of truth for socket event shapes and the `CLOTH_COLORS` palette.
- `artifacts/jpo-huddle/public/assets/JPO_HQ.tmj` — the Tiled map (210×128 tiles, Floor/Furniture/Wall layers, 13 embedded tilesets). Source of truth for room layout, furniture, walkable paths. The old `Office.tmj` stays on disk ONLY as a rollback — nothing references it.
- `lib/db/src/schema/jpoPlayers.ts`, `jpoAnnouncements.ts` — Drizzle table definitions (DB schema source of truth) so `drizzle-kit push` works; the game server itself uses raw SQL.

## Architecture decisions

- **DB is the source of truth; in-memory maps (`players`, `pending`, `admins`) are only a live-connection cache.** Every durable field is read from / written to Postgres.
- **`server.js` uses a raw `pg` Pool, not Drizzle** — keeps the server transpile-free while sharing the `@workspace/db` schema for `push`/migrations.
- **Identity key = lowercased email** (`jpo_players.email` is the PK). An approved email auto-restores straight into the office on register; `restorePlayer()` is the single seam, the identity gate lives in the `register` handler.
- **Kick = revoke** (flips `approved` back to `false`) — otherwise auto-restore would let a kicked player walk right back in.
- **Coin/position writes batch to the once-per-minute coin tick** (+ final flush on disconnect). Coin awards and purchases use atomic relative SQL (`coins = coins + N … RETURNING`) so ticks and buys can't race.
- **One live session per email:** a new connection disconnects the older socket (`dropLiveByEmail`).

- Cafeteria kitchen = paid food court: ten stations (candy stand, dessert counter, serving line 🍽️, two grill-bank anchors, produce crates, three bakery-line anchors, drink coolers 🧊) each open a server-sent 6-item menu on E; items cost 2–12 🪙, purchases are atomic conditional UPDATEs, and everyone nearby sees the food emoji bubble. No cooldown on paid food — the price is the limiter.
- Seating everywhere: every chair, stool, sofa, bench and armchair is sittable with correct facing (E key); beds give a lying pose with a 💤 chip. Base walk speed 195 px/s.
- Mini-game duels with optional wagers (0–10,000, capped by both balances): RPS, Tic-Tac-Toe, Quick Draw, Icebreakers, Word Race, Trivia Duel, Connect Four. Challenge via avatar click or the ⚔️ button; 30s accept window; per-game move/round timers with forfeit on timeout; winner takes the wager atomically; draws move nothing; shop purchases blocked mid-match.
- Office After Dark: Among Us-style round from the 🌙 button. 30s join window (min 3); lights go out for participants (pitch-black outside a small circle around your own avatar); 1 killer per ~3 players (3–4 → 1, 5–7 → 2, 8–10 → 3), drawn excluding last round's killers when the pool allows. Killers know their accomplices (named, un-targetable) and see a persistent 🔪 HUD chip + always-visible kill button (K, 200px, 12s per-killer cooldown = arm delay); crew only know "someone isn't friendly". A killer leaving forfeits only their own spot — crew auto-win only when the LAST killer leaves; the end card names ALL killers. Chat isolation while live: players in the dark hear only each other; whispers into the dark are refused. One round at a time, server-wide.
- Communication: public chat bubbles; private whispers (Tab / avatar-click menu, session-only, never stored); a client-only chat history log (💬 button / C key, session-only); announcement boards scoped to board clusters, posted by admins/announcers.
- Profiles & departments: fixed department list (HR, IT, Operations, Front Desk, CMA, QA, L&D, Claims, Accounting) picked at registration; legacy accounts get a one-time picker. Profile card: display name, dept, coins, worn cosmetic, join date.
- Everything durable survives restarts (coins, cosmetics, pets, outfit, announcer status, position). Auto-rejoin token + ~10s disconnect grace keep sessions seamless. The office is split into named room zones with floating labels.

## Gotchas

Places where two independent pieces of code must stay in lockstep, plus accepted tradeoffs.

### Networking & socket safety

- **Never destructure raw socket payloads in the handler parameter list** — `({ x } = {}) =>` still throws on an explicit `null` payload (was a live DoS). Every handler takes `(payload)` and destructures from `payload || {}`.
- **Whisper targets are socket ids, not names.** Autocomplete binds `_dmTargetId` to a live session (the `_online` roster mirrors `_addOtherPlayer`'s skip rules); ambiguous typed names are rejected, never guessed. Server delivers via `io.to(targetId)` only and shares the sender's `chatBucket`; grace-window targets get the friendly "not in the office" error by design. Chat, DM composer, panels, and the shop are mutually exclusive.
- **The chat history log is PASSIVE and client-only by design** (user declined persistence). It's an ADDITIONAL DOM-level `chatMessage` listener + `_chatLogAdd` hooks in the whisper handlers; no input field, so it joins none of the `chatting` mutual-exclusion seams. `textContent` only, capped at `CHATLOG_MAX` (200) nodes, auto-scroll only when already at bottom. C-key guards on `body.playing` + no input focus; its Esc-close yields to every other panel flag.
- **Display name ≠ full name.** `rowToPlayerState`: `name = nickname || first_name || name` (nametags/chat); `fullName` is for the admin panel. Announcements snapshot the author's display name at post time (accepted: old posts keep old names).
- **Empty-email clients get session-only play** (email is the PK); only affects non-standard clients.
- **Stale-client self-heal runs on page load AND socket reconnect.** Server injects `BUILD_STAMP` + serves `/stamp`; `_checkStamp()` force-reloads on mismatch (reconnect hook exists because weeks-old open tabs shipped stale clients). `BUILD_STAMP` is per-process, so autoscale instances differ — the `jpo_cb_at` sessionStorage guard (one reload / 5 min / tab) prevents reload loops; keep it.

### Auth & sessions

- **Password auth with a legacy-claim (TOFU) rule.** `password_hash IS NULL` = claimable legacy account; the first register claims it atomically (`UPDATE … WHERE password_hash IS NULL RETURNING`; a lost race verifies against the winner's hash). Password verification runs BEFORE any profile mutation or `dropLiveByEmail`. The per-email limiter (5 attempts/30s) is checked BEFORE any scrypt call (protects the libuv threadpool) and counts successful auths too — not a bug. Plaintext over socket.io is fine (WSS terminates TLS at the proxy).
- **Pending queue is DB-backed; `dismissed` decides who shows.** `_pendingList()` merges live pending sockets with `approved = false AND dismissed = false` rows; offline rows get id `email:<email>` (approve also falls back to any live pending socket for that email). Reject/kick set `dismissed = true`; ANY active return clears it. The column self-heals via an idempotent boot `ALTER TABLE`; legacy unapproved rows resurface once. SECURITY seam: `email:<address>` ids live in inline `onclick='…'` attributes — client `esc()` MUST escape single quotes and server `EMAIL_RE` must stay strict; keep both.
- **Admin status must be re-asserted on every reconnect** (the `admins` set is per-socket, in-memory). Client keeps `_adminPwd` memory-only and re-emits `adminAuth` on connect; `adminAuthOk` distinguishes manual unlock from silent re-auth; failed silent re-auth resets `_adminAuthed`. The new-registration toast keys pending by `email || id` (socket ids churn).
- **The admin-unlock input must stay `type="text"` + `-webkit-text-security`** — as a real password field Chrome popped "Save password?" on every chat send. `closeOwnerPwd()` wipes the value on close; keep both.
- **Admin password reset = clear hash + void all tokens.** Sets `password_hash = NULL`, `password_set_at = now()`, drops live sessions; `resumeSession` rejects tokens with `iat < password_set_at`. That's why `password_set_at` exists — don't repurpose it.
- **Resume tokens & the grace window are UX continuity, NOT primary auth.** HMAC token (via `SESSION_SECRET`) replayed on load; "Remember me" picks localStorage vs sessionStorage (saving to one clears the other). Tokens die on `TOKEN_MAX_AGE_MS` or `iat < password_set_at`, and are cleared client-side on kick/reject. Disconnects park email-backed players in a ~10s `GRACE_MS` window (`graceByEmail`) so a refresh resumes the SAME session without the avatar vanishing.

### Movement & anti-cheat

- **Server checks are sanity guards, NOT authoritative simulation.** Token buckets throttle chat/buy/post (excess silently dropped, never disconnected); `playerMove` validates min interval + bounds + impossible jumps, and rejections just drop (no rubber-banding). Lockstep: bounds derive from `JPO_HQ.tmj` × `RENDER_SCALE` which MUST equal the client's `setScale(3)`; `MOVE_SPEED` MUST equal client `SPEED`. Per-move budget ≈ `MOVE_SPEED·elapsed·tolerance` + jitter floor; the ~1-tile seat snap allowance applies ONLY on sit↔stand transitions (via `anim === 'sit'`), cooldown-gated. The FIRST `playerMove` is a bounds-only baseline (client spawn ≠ restored coords). Residual: a few-tiles banked teleport is still possible (authoritative movement out of scope).
- **Client `COFFEE_MULT` must equal server's (1.4)** — the server widens the move budget by the same multiplier until `boostUntil` + `BOOST_GRACE_MS`. Boost/smoke state is in-memory only (restart/refresh forfeits — accepted). Usable-item ids must match across server `USABLE_ITEMS`, client `_renderItemBar`, and the item-bar row ids.
- **Outdoor detection finds the `Ext` tileset BY NAME and bounds its gid range to the NEXT tileset's firstgid** (currently [8161, 8293)); `isOutdoors` samples the FEET tile (`(y + BODY_DY=27) / 48`). Appending tilesets after `Ext` is safe now, but renaming `Ext` or painting grass from another tileset silently breaks smoking detection.
- **Work bonus: server `WORK_SEAT_GIDS` {2231, 2763, 2764, 2628, 2600, 5033} must equal client `WORK_CHAIR_GIDS` — MINUS the client-only alias tiles** (client also lists 2644, 2584/2616, 5016/5017/5032 to drive the 💼 chip from the tile you press E on; the server derives the seat from the FINAL position, which always lands on 2628 for the right pod chair, 2600 for the left pod chair stack, and 5033 for the studio armchair — its centered sit puts x exactly on the two-tile boundary and `Math.round` picks the RIGHT tile; never add aliases server-side). (`DESK_FAMILIES` is EMPTY — kept only as a seam; 2584/2600/2616 is the pod LEFT chair stack, NOT a desk sprite.) WALL-layer desk chairs pay it too: server `WALL_WORK_SEAT_GIDS` {5533, 5564, 5565} ORs the Wall layer into the work-seat mask and must equal the client's `WALL_SEATS` keys. The server inverts the client's seated-sprite placement and requires `anim === 'sit'`; a re-imported map with new chair gids silently breaks it. Plain-table 2231 chairs (no monitor) also pay the bonus — accepted, same class as AFK-sit farming. Daily bonus = one atomic conditional UPDATE on `last_daily_bonus` vs DB `CURRENT_DATE` (UTC).

### Office After Dark rounds

- **The round engine follows the same double-settle discipline as `finishMatch`:** `endRound` flips `round.state = 'ending'` SYNCHRONOUSLY before any await; every other mutator re-checks `state === 'active'` first. Round⇄duel exclusion is symmetric via `rpsBySocket` at pending time; `rpsRespond` deliberately has no `inRound` check (unreachable mid-round) — don't "fix" it.
- **Killer identity is secret until `roundEnd`.** Role goes per-socket in `roundBegin` only (killers also get `accomplices` [{id,name}] — the one sanctioned leak, killers-to-killers); the shared roster carries `{id, name, alive}` only; non-killer `roundKill` probes are dropped SILENTLY. Kill cooldown is PER KILLER (`killReadyAt` on the member record) and its restart is a PRIVATE `roundKillCooldown` ping to the striker only. End-card names come from `round.killerNameOf` (draw-time snapshot) because leavers are deleted from `members`/`killerIds` immediately — that's also why payout winners = members ∩ killerIds (leavers forfeit the prize but still get named).
- **`roundHandleLeave` hooks the same three seams as `cancelMatchFor`** (disconnect, `kickPlayer`, `dropLiveByEmail`) and keys off `round.members`. Client `_roundReset()` is the single teardown. The darkness overlay is one fixed div repositioned per frame — valid only under `Phaser.Scale.RESIZE` (1 game px = 1 CSS px). It's PITCH BLACK by design (clear to 105px, opaque from 235px): a victim near max kill range is deliberately obscured — don't "fix" killer visibility by widening the hole.
- **Ghost hiding is CLIENT-side rendering only** (`_roundHiddenIds` + re-assert on the 250ms HUD tick, `_addOtherPlayer` gate, and per-`playerMoved` re-hide — `_placeWearable` re-shows sprites on every move). Server still broadcasts ghost moves (accepted v1). An eliminated player who refreshes mid-round returns as a visible NON-participant (accepted). `roundLobby` is `io.emit` on purpose (count only) — never add role/member data to it.
- **`ROUND_JOIN_MS` / `ROUND_DURATION_MS` env overrides are TEST KNOBS ONLY** — never set in production. Other round constants travel to the client in the `roundBegin` payload, so it never hardcodes stale values.
- **Round chat isolation is enforced SERVER-side at delivery time** (`inTheDark(id)` = alive member of the active round). Chat from anyone NOT in the dark skips in-the-dark recipients; whispers into the dark are refused with `whisperFailed`. Dark→dark and dark→outside stay open. Eliminated ghosts count as outside (dead-can't-snitch). Route any NEW broadcast channel through the same rule.
- **The killer draw excludes ALL of last round's killers** (`lastKillerKeys` by email; falls back to the full pool when exclusion would leave < killerCount+1 candidates). Killer count = `killerCountFor(n)` = `1 + floor(max(0, n-2)/3)`; Fisher-Yates shuffle takes the first killerCount. In-memory only — one possible repeat after a redeploy, accepted.
- **The server-side kill check allows range + slack (200+80px), NOT the bare range** — the killer's server position lags mid-chase and legit kills were rejected without it. `roundBegin` advertises only `killRangePx` (200), so a modified client gains at most 80px.
- **Killer speed edge (`ROUND_KILLER_SPEED_MULT` 1.15) is PRIVATE** — sent only in the killers' `roundBegin` payload (`speedMult`), like `accomplices`. The playerMove budget and client speed calc must stay mirrored: alive killer = max(edge, live coffee boost) — larger-of-two, never the product; alive crew = clamped to base (a pre-round boost timer resumes after the round; the client hides the boost chip meanwhile). Boost items + coffee machine are refused for EVERYONE in the dark with one identical "🌙 Too dark to brew" message (a role-split refusal or a mid-round ☕ bubble would out a killer — `coffeeBoost` is io.emit); group boosts skip in-the-dark recipients (ghosts still get them). All gates run before any charge/cooldown spend. Accepted residual: a spectator timing `playerMoved` deltas could infer the killer from the 15% pace (same class as the broadcast-ghost-moves tradeoff).

### Cosmetics, shop & wardrobe

- **Server `EMOTES` allowlist ↔ client `EMOTES` array lockstep** (number keys 1–8 map to array order). Emote bubbles reuse the chat-bubble slot on purpose — one replaces the other.
- **Client and server `DEPARTMENTS` lists must stay identical (values AND order).** Both write paths allowlist (`register` → `''`; `setDepartment` → silent drop), so the DB only holds fixed strings or `''`. "Set once" applies only to `setDepartment` (atomic `WHERE department=''`); a re-register CAN overwrite (same accepted seam as wardrobe colours). The profile card is non-blocking (no exclusion seams, no Esc), z-index below the rps modals, `textContent` only; `getProfile`/`setDepartment` share `profileBucket`.
- **Wardrobe seams.** Server `changeOutfit` silently REJECTS invalid indexes (not clamped). Re-rendering leans on the 50ms move stream: `_applyRemoteOutfit` only swaps `entry.texKey`, `_applyLocalOutfit` only calls `setTexture` when standing-idle — every other pose re-derives from `texKey` each tick; don't add explicit re-posing. Client price constants are display-only; server `WARDROBE_PRICE` is authoritative. The live preview reuses the registration recolor pipeline and never touches Phaser textures until the server confirms. Accepted residual: re-registering via Join re-applies form colours over a bought outfit.
- **Server `SHOP` ↔ client `COSMETICS` lockstep** (server authoritative; drift only breaks UI). Rendering is driven ONLY by `equipped_cosmetic` ('' = none); the owned array renders nothing. Buying auto-equips in the same atomic UPDATE as the spend; `equipCosmetic` enforces ownership in its WHERE clause and is deliberately NOT blocked mid-match (no coins move — only `buyCosmetic` keeps the `rpsBySocket` block).
- **Sprite wearables are a client-side rendering branch, not a server concept.** `WEARABLE_DEFS` decides which cosmetic ids render as pixel-art overlays; ids not in it fall back to the emoji path. A new sprite wearable needs FOUR things: server `SHOP` entry, client `COSMETICS` row, `WEARABLE_DEFS` entry, preloaded PNG. PNGs are TWO-frame sheets (frame 0 = front, frame 1 = side facing RIGHT, flipped for left, hidden facing up) — a single-frame PNG silently renders garbage. Every `dy`/`sideDy` is EMPIRICAL — sweep values live and screenshot all three facings. The chat-bubble lift applies only to emoji cosmetics.
- **Client `USABLES` ↔ server `USABLE_ITEMS` lockstep** (client costs display-only). Group use: server computes `nearbyIds(GROUP_RADIUS≈420px)` from LIVE positions at the moment of use, decrements the charge atomically, emits one `coffeeBoost` per recipient + one `groupEffect` visual for everyone. `boostUntil` max-extends (a coffee round can never shorten a pizza boost). Effect gates run before the charge decrement — a rejected use never burns a charge.
- **Server `PETS` ↔ client `PETS` lockstep.** Pet ids carry the `pet_` prefix ON PURPOSE: pets share the `cosmetics` array with wearables and the prefix keeps the id spaces disjoint (`buyCosmetic` rejects `pet_*`, `buyPet` rejects non-`pet_*` — keep both guards). Active pet = separate `equipped_pet` slot; `buyPet`/`equipPet` mirror the cosmetic pair exactly. Pet MOTION is never networked — each client derives trailing positions locally; only `playerPetUpdate` crosses the wire. Seated owners widen the pet's stand-off ring (`PET_SIT_GAP` 58 vs `PET_GAP` 36) and `_stepPet` pushes the pet OUT to it — otherwise the walk-trail gap parks the emoji ON the seated body (pets draw at depth 2, above players). Remote seated state rides the existing stream as `entry.seated` (`anim === 'sit'` in `playerMoved`/`_addOtherPlayer`); no new events. The server knows nothing about shop tabs; a new catalog entry lands on the right tab automatically, but a NEW tab means touching `#shop-tabs`, pane toggling, and the pager pick in `_refreshShopUI`.

### Mini-games (RPS / TTT / Quick Draw / Icebreakers / Word Race / Trivia / Connect Four)

- **ALL matches live only in `rpsBySocket`** (both ids → same match object, `game` field from the server `GAMES` allowlist). ONE lifecycle: `disconnect`, `kickPlayer`, `dropLiveByEmail` all run `cancelMatchFor` — mid-match disconnect cancels with no coins moved (the grace window does NOT keep matches alive); a match in `settling` is never cancelled. Accepted: a losing ttt player can disconnect to void the match (no coin gain possible). `buyCosmetic` is rejected mid-match — that keeps the accept-time balance check sufficient (the coin tick only ADDs). Settlement is SQL-first (CTE with `coins >= wager` guard); in-memory coins only update from `RETURNING`; the wager is re-verified at accept time. The challenge bucket is checked before all validation.
- **Every game-over path MUST route through `finishMatch`,** which flips `m.state = 'settling'` SYNCHRONOUSLY before its first await — the only thing preventing a disconnect-race on the wager transfer. Never settle inline in a handler.
- **Round-based games (ib/trivia) use `roundTimer`/`revealTimer`; ttt/c4 use `moveTimer`** — all cleared by `clearMatchTimers`, and every timer callback captures its round and re-checks `state`/`game`/round at fire time (stale timers are no-ops; keep the pattern). `IB_PROMPTS`/`WR_WORDS`/`TRIV_QS` are server-only content — growing a pool needs NO client change. The wr answer and trivia correct-index never leave the server before reveal. wr's input toggles Phaser key capture on focus/blur and is blurred by `rpsResult`/`closeAllRps` (a cancelled match can't capture the keyboard). ib/trivia/c4 in-game intents need no rate bucket — first-submit locks / turn gating make spam O(1) no-ops.
- **New games reuse the `rps*` event names on purpose** (`rpsChallenge` carries `game`; one `rpsResult` renders all verdicts; only in-game intents are new). Client `GAME_META` ↔ server `GAMES` lockstep; client `CHALLENGE_RANGE_PX` must equal server `RPS_RANGE_PX` (480). Arcade passes `game` through `interact` into `startRpsChallenge`; arcade matches are always 0-wager.

### Sprites & rendering

- **Seated poses reuse Adam's geometry for every character** — non-Adam seated sheets are recolours, `_sitZones` retunes only Y-bands (`SIT_ANATOMY` = generator HAIRMAX: right/down→y22, up→y17). Regenerating PNGs must keep HAIRMAX in lockstep.
- **Seated shirt/pants zones MUST keep `yMin = hairYMax`** — darker hair shades can fall inside the shirt threshold (e.g. Alex), and a customized shirt with default hair would repaint the hair. Costs a ~2px shoulder seam, accepted. See the comment above `_sitZones`.
- **Amelia's seated hair is short** (inherits Adam's silhouette) — accepted scope tradeoff.

### Ops & tooling
